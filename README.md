# ⚡ 电力市场研究前沿追踪

一个**本地运行、每日自动更新**的文献追踪网站：自动到国际学术数据源检索电力市场
（Electricity Market）方向的最新论文，计算热点与趋势，生成一个可以随时打开的静态网页。

所有数据都保存在你自己的电脑上，不需要服务器，不需要账号，也不会上传任何内容。

> 面向普通使用者的完整操作说明见 **`使用说明.md`**。

---

## 一、快速开始（3 步）

1. 确认电脑装了 **Python 3.9 或更高版本**（安装时勾选 *Add Python to PATH*）。
2. 双击 **`一键更新.bat`**。首次抓取约需 2—5 分钟，结束后会自动打开网站。
3. 以后想看最新文献，再双击一次 `一键更新.bat` 即可（日常增量更新通常 1—2 分钟）。

如果希望同时把最新数据同步到 GitHub Pages，供手机访问，请双击
**`一键更新并同步到GitHub.bat`**。

> 只想先看看界面长什么样？直接双击 **`打开网站.bat`**，页面会显示一组
> 明确标注为「演示数据」的占位内容，帮你预览布局。抓取到真实文献后会自动切换。

## 二、设置每天自动更新

双击 **`注册每日更新任务.bat`**，按提示输入时间（默认 08:30），会在 Windows
任务计划程序里创建一个名为 `PowerMarketRadar-Daily` 的任务。

* 任务需要**电脑开机且已登录**才会执行；错过的时间点不会自动补跑。
* 运行日志写在 `logs/update.log`。
* 想取消：双击 **`取消每日更新任务.bat`**。
* 想查看状态：在项目目录执行 `python crawler\schedule.py status`。

## 三、网站能做什么

| 功能 | 说明 |
| --- | --- |
| 热点主题排行 | 18 个研究方向的实时热度榜，按「产出量 × 增长动能 × 影响力」打分，并标注升温／降温 |
| 12 个月趋势图 | 各主题逐月论文数量，点击图例可临时隐藏某条曲线 |
| 上升关键词 | 自动对比近半年与前半年，挖出正在冒头的新术语（不依赖预设词表） |
| 多维筛选 | 关键词、时间范围、主题标签、数据源、只看收藏／未读／今日新增 |
| 五种排序 | 最新发表、相关度、总被引、引用速度、重点期刊优先 |
| 中英关键词打通 | 输入「现货」「储能」「碳市场」等中文词，会自动映射到英文检索词 |
| 收藏与已读 | 保存在浏览器本地，下次打开仍在 |
| 一键导出 | 收藏文献可导出为 **BibTeX / Markdown / CSV / 参考文献**四种格式 |
| 中文库直达 | 一键跳转知网、万方、百度学术、Google 学术检索同一主题（国际库对中文期刊覆盖有限） |

快捷键：按 `/` 直接跳到搜索框，按 `Esc` 关闭弹窗。

## 四、数据从哪来

| 数据源 | 作用 | 是否需要 Key |
| --- | --- | --- |
| **OpenAlex** | 主源，覆盖面最广，含期刊论文、预印本与被引数 | 不需要 |
| **arXiv** | 预印本，最快反映前沿动向 | 不需要 |
| **Crossref** | 期刊元数据补充、DOI 校验 | 不需要 |
| Semantic Scholar | 可选，默认关闭（限流严格） | 需要时设环境变量 `S2_API_KEY` |

检索逻辑：

1. 按 `crawler/config.py` 里的 **18 个主题方向**分别检索，每个方向取
   「最近 540 天的最新文献」+「近 6 年高被引文献」+「最新预印本」三批；
2. 用 DOI 和标题归一化做**跨源去重**，同一篇论文只保留信息最全的一条；
3. 按关键词给文献**打主题标签**（标题命中权重翻倍，一篇可归入多个主题）；
4. 结果存入本地 SQLite（`data/library.db`），记录首次收录时间，从而算出"今日新增"；
5. 计算热点分、月度趋势、上升关键词，导出成网页数据。

**热点分公式**：`0.38 × 产出量 + 0.30 × 增长动能 + 0.20 × 引用影响力 + 0.12 × 重点期刊占比`
（各项先做对数归一化）。单纯比数量会被沉淀多年的老方向淹没，所以"增长动能"
用近 30 天月均产出对比此前 90 天月均产出，专门捕捉正在变热的方向。

## 五、想改点什么

**扩展研究范围** —— 编辑 `crawler/config.py` 里的 `TOPICS`，加一条：

```python
{
    "id": "my_topic",
    "zh": "我的方向",
    "color": "#ff8800",
    "queries": ["英文检索短语1", "英文检索短语2"],   # 拿去各数据库检索
    "keywords": ["匹配关键词", "中文词也可"],          # 用于给文献打标签
},
```

**调整抓取规模** —— 同文件顶部：`RECENT_DAYS`（回看天数）、`PER_TOPIC_RECENT`
（每主题抓多少最新文献）、`SOURCES`（开关各数据源）。

**只抓某几个方向**（调试时很快）：

```
python crawler\run.py --topics spot_market,ai
```

**其他常用命令**

```
python crawler\run.py --list-topics   # 列出全部主题 id
python crawler\run.py --offline       # 不联网，只用本地库重建网站
python crawler\run.py --fresh         # 清空本地库重新抓取
python crawler\selftest.py            # 离线自检，不联网验证整条流水线
```

## 七、常见问题

**更新时报"检测不到网络连接"**
检查网络或代理是否正常。注意爬虫用的是命令行环境，如果浏览器走了代理软件、
而命令行没走，需要先让系统代理生效（例如在 v2rayN 等工具中开启"系统代理"）。
网络恢复后重新双击 `一键更新.bat` 即可；之前抓到的数据不会丢。

新版爬虫默认不会盲目继承 Windows 注册表里的残留代理，而是优先直连，并读取
标准的 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。需要强制指定时，可在运行前设置：

```
set PMR_PROXY=http://127.0.0.1:7890
set PMR_PROXY_MODE=direct   # 或 system，使用系统代理
```

**arXiv 连接失败**
部分校园网、公司网络会重置 `export.arxiv.org` 连接。程序会连续失败两次后
自动跳过 arXiv，并用 OpenAlex 中的预印本补足前沿内容，不影响其余来源更新。
页面顶部的提示条可关闭；当网络允许访问 arXiv 后，下次更新会自动重试。

**中文文献很少**
OpenAlex / arXiv 对中文期刊收录有限，这是数据源本身的限制。可以在网站右侧
「中文库直达检索」中，用同一主题去知网、万方继续检索。

**某个数据源报错，其他正常**
属正常情况。单个源失败会被跳过并记录在页面顶部的提示条里，不影响其他结果，
下次运行会自动重试。

**今日新增一直是 0**
说明本次抓取没有发现上次之后新收录的文献，不是故障。arXiv 预印本和期刊
上线都有周期，一般每周会有明显新增。

**想换台电脑用**
整个文件夹拷过去即可，`data/` 目录里带着完整历史，不需要重新抓全量。

**网站打开是空白 / 数据不更新**
网站读的是 `data/data.js`。确认它存在且不是 0 字节；若刚改过代码，
重新运行一次 `一键更新.bat` 或 `python crawler\run.py --offline` 重新生成。
